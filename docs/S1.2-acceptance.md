# S1.2 验收清单

## 范围

仅数据模型：Flyway V3、JPA Entity、Repository、约束与自动化测试。

**不包含**：微信 OAuth、登录 API、Token 签发、设备采集、72h 试用计算、会员/支付。

## 人工验收步骤（Windows）

```powershell
cd D:\Android_Work_Server\AuroraAppServer

# 1) 开发库（若未启动）
docker compose -f docker-compose.dev.yml up -d

# 2) 启动 Server（会自动执行 Flyway V3）
$env:GRADLE_USER_HOME = "D:\Android_Work_Server\.gradle-home"
.\gradlew.bat bootRun

# 3) 健康检查
Invoke-RestMethod http://localhost:8080/actuator/health
```

Navicat 连接 `127.0.0.1:3308` / `aurora_app`，确认：

1. `flyway_schema_history` 有 V3 成功记录  
2. 四张新表存在  
3. 尝试跨 App 插入会话/微信身份应失败  

自动化：

```powershell
docker compose -f docker-compose.test.yml up -d
.\gradlew.bat test
```

## S2.1 如何使用这些模型（预告，本 Task 不实现）

1. 微信登录成功后：在对应 `app_id` 下创建/查找 `users` + `wechat_identities`。  
2. 签发 Token：只存 `token_hash` 到 `auth_sessions`，会话行写入服务端可信 `app_id`。  
3. 受保护 API：用 Token 查会话 → 校验未过期/未吊销 → 以会话 `app_id`/`user_id` 访问资源。  
4. 设备试用：只存 `device_key_hash`，按 `app_id` 读写 `device_trials` 并计算过期时间。  
5. 永远不要信任客户端提交的 `app_id` 覆盖会话归属。
