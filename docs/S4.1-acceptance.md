# S4.1 验收说明 · 多应用会员权益基础

## 交付范围

- Flyway `V4__create_membership_tables.sql`（plans / grants / entitlements + CalculatorVault 套餐种子）
- `MembershipService`：grant / revoke / getStatus（叠加、永久优先、幂等、并发）
- `GET /api/v1/membership/me`（需登录）
- 文档与自动化测试

**不包含：** 支付、订单、公开发放 API、Android 接入、试用改造。

## 人工验收步骤

1. 确认测试库已跑通 Flyway V4（`docker compose -f docker-compose.test.yml up -d` 后执行测试）。
2. 全量测试：`.\gradlew.bat test`（或项目惯用脚本），预期 **原 58 + S4.1 新增用例全部通过**。
3. 登录后查询无会员：

```http
GET /api/v1/membership/me
X-App-Code: calculator_vault
Authorization: Bearer <token>
```

期望 `status=NONE`。

4. 在测试环境通过内部 Service（集成测试或临时调试）发放月卡，再调 `/me`，期望 `ACTIVE`、到期为发放时间 + 30 天。
5. 确认 `POST /api/v1/membership/grant`、`/revoke` 返回 404（客户端不可发放/撤销）。
6. 用 App A Token + App B 的 `X-App-Code` 访问 `/me`，期望 `40301 APP_CONTEXT_MISMATCH`。
7. 确认退出登录后再登录，会员状态仍可从 Server 恢复（库记录未因 logout 删除）。

## 已知风险 / 后续待办

- 无订单表时，`order_id` 仅为预留字段；真实支付需 S4.2+ 订单与回调。
- 叠加撤销按「账本重放」语义，与部分「按日历段切割」产品口径不同，接入前需与产品确认。
- `TEST` 来源依赖 Spring profile 判断，生产部署勿启用 `local`/`dev`/`test` profile。
- 未实现管理后台与人工发放 HTTP API。
